1. Executive Summary  
The Assist platform currently handles 6 general HR processes:  
1. Reference Letters  
2. Compensation Letters  
3. Separation Letters  
4. Maternity Leave Request  
5. Salary Advance Request  
6. Resignation Request  
and is scheduled for decommission by June 2026.  
This discovery initiative documents the analysis, findings, and migration strategy to transition all processes to the centralized DOCS (Document  
Management) system and other integrated solutions within the EPAM ecosystem. The goal is to ensure zero disruption to end-user experience,  
maintain data integrity, and reduce operational overhead.  
2. Background & Context  
Why this discovery was initiated: The Assist platform is a legacy system built for one geographic location (India), that needs to be retired. Maintaining it  
incurs ongoing operational overhead, and its processes need to be absorbed by modern, integrated solutions unified and consistent across all Epam  
locations.  
Business drivers for decommissioning:  
Eliminate maintenance costs of the legacy Assist platform  
Consolidate HR processes into the existing EPAM ecosystem (DOCS, ServiceNow, HRMS)  
Improve user experience with streamlined, self-service workflows  
Timeline: Discovery initiated in Q1'2026, with full platform decommission targeted for June 2026.

4. Problem Statement  
Description: The Assist platform currently handles 6 general HR processes. It needs to be decommissioned by June 2026. The platform requires migration  
of these processes to integrated solutions within the existing EPAM ecosystem to improve efficiency and user experience.  
Impact:  
Impact Area  
Description  
Operational Impact Disruption to daily HR operations if migration is not handled properly  
User Impact  
Potential confusion and workflow interruption for employees using these services  
Risk of process gaps during transition period  
Process Impact  
Resource Impact  
Maintenance overhead of legacy system until proper migration  
Compliance Impact Ensuring continuity of critical HR processes without regulatory gaps  
5. Discovery Objectives  
What the team aimed to discover/validate:  
Full inventory of all Assist platform processes, letters, and workflows  
Identify which processes migrate to DOCS  
Determine must-have vs. nice-to-have requirements for MVP  
Identify approval workflows and role-based access needs  
Assess integration requirements and technical dependencies  
Key questions to answer:  
Which processes can be handled by DOCS Self-Service?  
Which processes require integration with third-party systems?  
What approval flows need to be preserved or changed?  
Is historical data migration required?
