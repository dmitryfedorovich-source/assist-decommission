10 — PO/BA Playbook

How to Use This System

A practical guide for the BA or PO running this project — when to feed information, how to create and update each output document, and when to validate.

📥

1 · Feed Inputs

When new information arrives — meeting transcripts, stakeholder corrections, Confluence pages, verbal decisions — drop it into the system. Claude extracts decisions and open questions, updates the Feedback Log, and flags what output docs need to change.

✍️

2 · Generate & Update Artifacts

With confirmed facts in memory, ask Claude to create or update the relevant output document. Load the phase state file and domain_rules first. The Feedback Log is the single source of truth — Claude never invents facts. Run /validate-docs after every change.

✅

3 · Verify & Sign Off

Run /validate-docs before every stakeholder stage. Fix all errors before sharing documents. Review warnings and accept or resolve each one. The validator reads the Feedback Log dynamically — no setup required.

Common Step-by-Step Workflows

🎙️ Process a Meeting Transcript

  1. Drop transcript file in input/transcriptions/
  2. Tell Claude: "Process the new transcript"
  3. Claude extracts D-XX / OQ-XX / F-XX → updates FDL → updates phase state → renames file with [processed]- prefix
  4. Run /validate-docs — check what output docs need updating
  5. Apply required fixes; re-run /validate-docs until clean

✏️ Apply Stakeholder Corrections

  1. Save correction image in input/corrections/
  2. Tell Claude: "Apply corrections from [filename]"
  3. Claude reads image → identifies changes → updates all affected output docs → logs F-XX in FDL
  4. Run /validate-docs to confirm corrections propagated cleanly across all docs

🔒 Add a Confirmed Decision

  1. Add D-XX entry to output/shared/Feedback_Decisions_Log.md (follow templates.md)
  2. Add matching row to output/shared/RTM.md
  3. Add entry to docs/data/decisions.yaml
  4. Run /validate-schema to confirm sync across all three files
  5. Run /validate-docs → update all flagged docs → re-run until clean

📋 Prepare for an India SME Meeting

  1. Run /validate-docs — resolve all errors first
  2. Review Open OQs in FDL with "Stage 2 review" as target resolution
  3. Confirm each open OQ has a corresponding question in 05_India_SME_Validation.md
  4. Check sign-off table in 05 has India stakeholder names
  5. Share 05 with Satish / Satya / Sasanka for review; record responses as new D-XX or OQ updates

Validation rule: Run /validate-docs after every change to any file in output/. This is the single quality gate for the entire documentation set. All ❌ errors must be fixed before sharing any document with a stakeholder. ⚠️ warnings must be reviewed and either resolved or explicitly accepted with a note in the FDL. Run /build-overview after any change to docs/src/ — never edit Project_Overview.html directly.
