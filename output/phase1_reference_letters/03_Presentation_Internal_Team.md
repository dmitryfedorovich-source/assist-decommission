## Slide 4 — Process Flow: People Team Verification (LOR)

```
Employee                DOCS Platform              People team (verifier)
   │                         │                      │
   ├─ Select letter type ────→│                      │
   │                         ├─ Create request       │
   ├─ Attach RM approval ────→│                      │
   ├─ Fill in form ──────────→│                      │
   │                         ├─ Route to verifier ──→│
   │                         │                      ├─ Review request + RM approval
   │                         │                      │
   │                         │    Verify + "Send Document" action
   │                         │←─────────────────────┤
   │                         ├─ Notify employee      │  Reject (required comment)
   ├─ Download letter ←───────┤                      ├──→ Notify employee
   │  (hidden until sent)    │                      │    (employee edits & resubmits same form)
```

**Used for:** LOR
> Document is **not visible** to the employee until the People team (verifier) explicitly triggers the "Send Document" action *(D-25)*.

## Slide 6 — Special Behaviors to Implement

**Address not found — Address Proof Letter**
- When People system returns no address: show error banner
- Message: employee must update their profile in People system before requesting

**Self-Declaration checkbox — confirmed present in DOCS (D-21)**
- Assist shows a confirmation popup with a checkbox before employees press "Continue"
- DOCS implements a **Self-Declaration section at the bottom of each request form** with a full disclaimer text and an **"Accept" checkbox** — the employee must tick it before clicking Submit
- This updates D-17: the checkbox consent IS present in DOCS, positioned at the bottom (not as a popup or static text at top)

**Custom purpose text — Address Proof Letter**
- Free-text field is always visible in the form (DOCS cannot conditionally show/hide fields)
- Max 100 characters — employee fills in when "Custom" is selected from Purpose dropdown

**Auto-close**
- Once all forms reach final status (Verified / Generated) → auto-close after **2 days** if not manually closed

**"System File" form component**
- Each DOCS request contains a second Required Form: **"System File"** — holds pre-populated People system data (First name, Last name, UID, Start date in EPAM India, Email address)
- Separate from the employee-filled "Request details" form; auto-visible to specialists; has a "Submit & Verify" button
- Platform team to confirm this component is included in request configuration for all 5 India letter types

**Status label after submit (auto-verified letters)**
- After employee submits, request shows **"Waiting for verification"** (not "Completed") until nightly batch job runs — this is expected platform behavior
- Letter document is **already downloadable immediately** after submission regardless of status label
- Note to include in employee-facing communications

**Save as draft**
- DOCS forms have a "Save as draft" button — employee can save progress and return before submitting

**New request cooldown**
- Employee cannot submit a new request for the same letter type until 2 days after previous request closes

**Rejection → Edit &amp; resubmit same form**
- Specialist rejects with required comment; employee edits same form and resubmits; specialist re-verifies. No limit on resubmissions.
